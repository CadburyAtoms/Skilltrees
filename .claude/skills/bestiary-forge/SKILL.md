# Bestiary-forge — one owner for the adversary surface

Written 2026-09-14 when Ben scoped the bestiary redo (TODO_REPO_HYGIENE item 121). Until then
four skills each held one layer of adversary work and none owned the numbers: concepts in
`lore-forge` (Phases 4b/4c), wiring in `leyline-tree-authoring` (§"Adversary abilities"),
encounters in `session-forge`, talent lists in `build-forge` (Phase 5). Those sections still
stand and this skill points at them — **it owns the statting standard, the census, the design
seeds, the yardstick, and the redo's plan**, and it is where the four layers meet.

| File here | What it is |
|---|---|
| `STANDARD.md` | What every block states, where each number comes from, which rule decides it — RULED / MEASURED / PENDING marked on every line. |
| `DESIGN_SEEDS.md` | The bestiary backlog for ideas with a source (R-76's drain ability and kin). |
| `TURN_LEDGER.md` | The recording template for a yardstick fight on copies of the actual PCs. |
| `docs/analysis/bestiary/CENSUS.md` | The measured ground truth, generated by `node scripts/bestiary-census.js --write`; stale = the census test fails. |

## Read first, every time

1. `docs/analysis/bestiary/CENSUS.md` — the roster, the role bands, the colour ledger, the wiring
   shapes, the sole consumers. Run `node scripts/bestiary-census.js --check` to be sure it is current.
2. `STANDARD.md` — and note which lines are PENDING a ruling. **A PENDING line is never applied to
   data before its ruling lands.**
3. `EDHA_RULINGS.md` §G and §K.15 — the adversary rulings. R-128 … R-135 were all answered (a) on
   2026-09-14; nothing is open. Do not build on an unanswered ruling; build the parts that do not
   depend on it.
4. The nation's canon cluster: `EDHA_CAMPAIGN_CANON.md` §5c "The <nation> …" — the approved
   creatures, their famine arcs, outs and counterplay. Canon creatures come pre-approved as concepts.
5. `EDHA_CAMPAIGN_STATE.md` §1 "The party as a shape" — Blue / White / Green, two Scholars and an
   Envoy, no fighter, no Black, no Red, and (until they shop) no ranged attack. Every number is read
   against them.
6. `EDHA_FOUNDRY_TEST_CHECKLIST.md` DEPLOY STATE and the bestiary sections — what is live, what is
   still owed a rebuild, which rows are shelved.
7. `leyline-tree-authoring` SKILL.md §"Adversary abilities" and ENGINE_INDEX §"Talents on
   adversaries" / §"GM cue cards" — before wiring anything.

## The loop

**Phase 0 — Sync and state.** `git pull`, `node scripts/gates.js` green, census `--check`, DEPLOY
STATE date against `git log`. If Ben's message is a bug report or test result, stop: that is
`test-pass-fixes`. If the task is to drive blocks live, stop: that is `bench-run`.

**Phase 1 — Frame the need.** Which nation, which session, which encounter shape (a pack, a pair,
a boss, a negotiation that is not a fight)? Read the ledger (census §3) and say what colour the
new entries should lean toward. Set the roster target (§1 of the standard) and name the
scenery-tier entries as scenery. Check `DESIGN_SEEDS.md` for a seed that fits.

**Phase 2 — Concepts (the lore gate).** For an invented creature, `lore-forge` Phase 4b: the
three-layer derivation, the famine or shift-clause arc derived from a named ruling, the kit of two
to four talents from its own colour tree. **Present the concepts to Ben as one menu and wait**;
invented world-content is never committed before his yes. A canon §5c creature skips this phase.

**Phase 3 — Stat the blocks (STANDARD.md).** Every field in §2 of the standard, every number
inside the role band unless the proposal says why not, dice by role rank, `movement` stated,
`senses` stated when the creature should not see 5 ft, immunities that bind, weapons as
`kind: "weapon"`, a biography with the outs and the tone line, a `count` for the reference
encounter. Humans: tree talents as written, checked with `python scripts/validate-build.py
--adversaries` (informational — R-94 lets them skip gates; the print tells you what it costs the
players). Beasts: adaptations as bespoke abilities carrying the source talent's rule shape.

**Phase 4 — Wire and prove.** Author `events` against the closed dispatch table (never by copying
a neighbour), `edha-gm-cue` at minimum where the call stays at the table, `noHook` with its reason
where no hook exists. `node scripts/gates.js`, then `node scripts/bestiary-census.js --write` and
**diff the census**: did a band move, did the ledger move, did a sole consumer appear? The diff is
part of the proposal.

**Phase 5 — The statblock gate.** Present the blocks in full — numbers, abilities, rules, the
census diff, the deploy class, the bench rows you will add. Ben reviews defenses, numbers and the
bespoke actions. **A yes on the creature was never a yes on its numbers.** Only after this yes:
commit (small, themed; data + census + docs together).

**Phase 6 — Ship.** Commit message and delta header say **adversaries REBUILD + ⟳ Sync Adversaries
(scoped)** or ENGINE-ONLY F5. One 🤖 row per new or changed block in the nation's bestiary section;
for a new roster, a yardstick fight row and a `TURN_LEDGER.md` recording. Art slugs into
`EDHA_ADVERSARY_ART_WISHLIST.md`. Canon §9 gets the ruling if one was made; `EDHA_RULINGS.md` gets
any decision Ben still owes. Dated delta at the top of `docs/handoff-changelog/2026-MM.md`.

## Traps — each one shipped at least once

- **Copying a neighbour's cue.** Six dead cues shipped in July because the pattern imitated was
  itself broken ("attack-hit" dispatches nothing). Author from the table; lint pass 6 is the net.
- **A raw `item.type === "talent"` gate.** Adversary abilities are action-typed twins; The
  Seeming's engine case was unreachable for two days. Every gate goes through `edhaIsTalent`.
- **Tier standing in for rank.** Ruling 107 made dice scale with tier; ruling 122 reversed it to
  role, and the older blocks needed a retro sweep (ruling 123). Say the resolution in the rule.
- **A ranked skill standing in for an attribute.** Attributes were 0 on every block, so `dec: 4`
  did the work of attribute + rank. R-128 (a) re-derives each to attribute + rank with the same
  total in its nation pass; until then, never call it a PC-legal rank.
- **The 5-ft stare.** An attribute-less block sees 5 ft in the dark on sheet and token alike since
  item 83. A wolf that sees 5 ft is a bug in the block, not in the ladder — state `senses`.
- **Schema notes drift.** The data file's own `_README` still said "10 ft" a week after item 83
  made it 5. When a rule changes, grep the note that explains the field.
- **Card and engine drift both ways.** Withering Ray's card lied; Predator's Due had events and no
  `damage` block. Decide which side is canonical, then align text, data and docs together.
- **"How does this feel" is not a test row.** Feel is ⚑ and needs play; a rule Ben can write now
  is a ruling. Five feel rows sat shelved because the two were mixed (R-133 splits them).
- **A cue is not automation.** A whispered card is the floor the standard allows, not the goal.
  Count cues and effects separately (the census does) and ask which cues are decision-free.
- **One bug or a family.** Three unrelated-looking adversary reports were one formula bug in the
  Black pass. Group by code path before fixing any.
